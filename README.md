# Pathfinder

Экспериментальный локальный инструмент для Windows: подбирает способ подключения к HTTPS-сайту, запоминает результат отдельно для каждой сети и повторяет поиск после сбоев. Управление — в терминале. Сервер Pathfinder арендовать не нужно.

**Статус: первый прототип.** Работа с реальными ограничениями конкретного российского провайдера ещё не подтверждена. Локальное дробление TLS — экспериментальная стратегия, оно не заменяет возможности zapret. Для смены внешнего IP нужен работающий внешний выход через отдельно запущенный SOCKS-клиент, например Tor. Pathfinder сам не устанавливает Tor, мосты, VPN или драйверы.

**0.1.1:** домены `.ru`, `.su`, `.рф`, VK и указанные в `direct_domains` файловые серверы открываются напрямую через браузер. Для них не выполняются предварительные TLS/HEAD-проверки и не выбирается внешний выход. Это правило исправляет слишком широкий охват прокси в первой версии; принадлежность всех российских сайтов автоматически не определяется.

Для обновления завершите старое меню через `0`, повторите команду установки ниже и перезапустите браузер, если он сохранил прежние соединения. Новые правила добавляются и в существующий config.json; настройки SOCKS сохраняются. URL PAC содержит номер версии, чтобы обновление не использовало старые правила из кеша.

## Установка одной командой

Откройте обычный PowerShell в Windows 10/11 x64 либо ARM64 и выполните:

```powershell
irm https://raw.githubusercontent.com/de1evly/ggbb/main/install.ps1 | iex
```

Git, GitHub CLI, вход в GitHub и заранее установленный Python не нужны. Репозиторий публичный. При ограничении анонимных запросов GitHub API установщик сообщит об ошибке; можно повторить позже либо скачать ZIP проекта и использовать `-LocalSource` ниже.

Установщик получает текущий commit SHA, скачивает исходники именно этой версии, проверяет Git blob SHA и загружает переносимый Python 3.14.10 с проверкой SHA-256. Исходники размещаются в `%LOCALAPPDATA%\PathfinderApp`, данные — в `%LOCALAPPDATA%\Pathfinder`. Системный Python и PATH не изменяются; `pip` и сторонние Python-пакеты не нужны. Хеши Python взяты из [официального манифеста](https://www.python.org/ftp/python/3.14.10/windows-3.14.10.json).

При первом запуске включается пользовательский прокси Windows и открывается меню. Это действует на приложения, которые учитывают системный PAC-прокси. Обычный выход через `0` или Ctrl+C восстанавливает прежние настройки. Запуск из распакованного проекта также возможен:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -LocalSource .
```

Последующие запуски:

```powershell
& "$env:LOCALAPPDATA\PathfinderApp\Pathfinder.cmd"
```

Для меню и сканирования без изменения настроек Windows:

```powershell
& "$env:LOCALAPPDATA\PathfinderApp\Pathfinder.cmd" -NoProxy
```

После аварийного закрытия окна, сбоя или остановки процесса:

```powershell
& "$env:LOCALAPPDATA\PathfinderApp\Pathfinder.cmd" -RestoreProxy
```

Если другой инструмент изменил прокси после Pathfinder, восстановление сохраняет эти чужие изменения. До выяснения причин не удаляйте `%LOCALAPPDATA%\Pathfinder\proxy-backup.json`.

## Меню

| Команда | Действие |
| --- | --- |
| 1 | Текущая сеть, сохранённые способы, количество сбоев |
| 2 | Проверить доступные способы для домена; действующий выбор не меняется |
| 3 | Повторно подобрать путь; существующие соединения остаются на прежнем |
| 4 / 5 | Включить / восстановить пользовательские настройки прокси Windows |
| 6 | Сохранить ZIP с диагностикой на этот компьютер |
| 7 | Последние проверки и ошибки |
| 8 | Ключ подключения необязательного расширения |
| 9 | Добавить уже запущенный SOCKS на loopback либо отключить его |
| 0 | Выйти и восстановить настройки прокси |

Сканирование означает несколько HTTPS HEAD-запросов к указанному домену. Это не сканирование чужих портов или сети. Проверки не используют ваши cookies, пароли и содержимое вкладок.

## Как выбирается путь

1. При первом обращении пробуются прямой IPv4, IPv4 с дроблением первого TLS ClientHello на две записи, IPv6 и включённый пользователем локальный SOCKS. У SOCKS доменное имя передаётся upstream-клиенту без локального DNS-разрешения.
2. Проверяется TLS-сертификат и ответ на `HEAD /` с ограничением времени. Успешный HTTP-ответ — свидетельство доступности проверенного адреса. Он не доказывает работу авторизации, видео, API и всех CDN сервиса.
3. Результат сохраняется в SQLite: отпечаток сети + конфигурация способов/групп + сервис. В версии 0.1 поддерживается один протокол, HTTPS поверх TCP на порту 443.
4. Сохранённый путь сразу используется повторно. Смена Wi-Fi/шлюза/сетевого профиля проверяется каждые 15 секунд. Отпечаток вычисляется локально и не отправляется наружу. При неоднозначном определении сети можно задать `network_label` вручную.
5. Два разделённых во времени транспортных сбоя запускают новый подбор. Залп ошибок считается одним событием. При полном отказе способов действует пауза от 30 секунд до 5 минут.
6. Недавно использованные маршруты дополнительно перепроверяются фоном: не чаще раза в 2 минуты, до 8 маршрутов за проход. Это позволяет замечать отказ без расширения. Для большого числа доменов задержка обнаружения увеличивается.
7. Активные TCP-соединения не переносятся на другой выход. Новые соединения могут перейти на найденный способ после отказа. Это не гарантирует постоянный IP всей учётной записи или всех связанных доменов. Программа не повторяет отправленные формы, платежи или другие запросы приложения.

HTTP 403 не объявляется геоблокировкой. Если все способы возвращают неоднозначные ответы, например HEAD 405, программа допускает загрузку сайта через один из ответивших путей и помечает результат `http_inconclusive`. Ошибка сертификата успешным результатом не считается.

Автоматический подбор выбирает из реализованных и включённых способов. Он не генерирует новые протоколы и не гарантирует доступ к любому ресурсу у любого провайдера.

## Ограничения версии 0.1

- Покрывается HTTPS на TCP 443 у приложений, поддерживающих HTTP CONNECT / системный PAC. UDP, QUIC, Discord voice, WebRTC и приложения с собственными сетевыми настройками не покрываются. Это не VPN и не режим гарантированной анонимности.
- HTTP без TLS, локальные имена и адреса обходят PAC напрямую. Публичное имя, которое резолвится в частный адрес, отклоняется прямым адаптером; для внутреннего корпоративного сайта может потребоваться отключение Pathfinder.
- Прямые способы сохраняют внешний IP провайдера. Географические ограничения по IP и полная блокировка IP могут требовать внешнего выхода. SOCKS-адаптер сам по себе не создаёт этот выход. Tor может быть недоступен или отвергнут целевым сайтом.
- HTTPS не расшифровывается прокси. Без расширения HTTP-ошибки реального запроса внутри туннеля не видны; доступны собственные периодические проверки. Отдельная функциональная проверка сервиса пока не реализована.
- Дробление TLS не отключает ECH и не подменяет SNI или сертификат. Некоторые серверы/сети могут не принять такой способ; тогда используются другие доступные варианты.
- Новый домен может открываться медленнее: выполняется проверка. Общий поиск ограничен 28 секундами. Нет скрытого прямого fallback в сформированном PAC для управляемого домена, но само приложение/ОС может иначе обработать недоступность PAC. Это не kill switch.
- При аварийном закрытии окна Windows-настройки могут сохраниться до `-RestoreProxy`. Рабочий процесс может остаться запущенным; следующее меню подключится к нему. Автозапуск и служба Windows пока не создаются.

## Настройки

Файл `%LOCALAPPDATA%\Pathfinder\config.json` создаётся при первом запуске. После ручного редактирования перезапустите движок. Меню настройки SOCKS применяет изменение сразу.

По умолчанию `auto_manage: true`: обрабатываются публичные HTTPS-домены, кроме списка `direct_domains`. Правила прямого доступа имеют приоритет над подбором и группами `services`; для включения обхода на конкретном исключённом домене нужно изменить этот список (например, убрать `*.ru`). Пустой список `direct_domains: []` отключает исключения и сохраняется при обновлении. Если нужно ограничить охват, задайте `auto_manage: false` и укажите группы `services`:

```json
{
  "id": "example",
  "domains": ["example.com", "*.example.com"],
  "probe_host": "example.com",
  "probe_path": "/",
  "expected_statuses": [200, 301, 302]
}
```

Это элемент массива `services`, а не весь config.json. Группируйте только известные связанные домены. Общий CDN автоматически не объединяется со всеми сайтами. Указанный `probe_path` должен быть безвредным и доступным без авторизации; перенаправления не проходят дополнительную проверку конечной страницы.

Для внешнего выхода запустите свой доверенный SOCKS-клиент, затем в меню `9` укажите его локальный порт. Значение 0 отключает его. Соединения с таким клиентом поддерживаются только по loopback, без SOCKS-аутентификации. Списки случайных публичных прокси не используются.

## Необязательное расширение Chrome / Edge

Откройте `chrome://extensions` либо `edge://extensions`, включите режим разработчика и загрузите папку `extension` из установленной версии в `%LOCALAPPDATA%\PathfinderApp\versions\<commit>`. Нажмите на расширение, вставьте ключ из пункта `8` консольного меню.

Расширение передаёт локальному движку результат загрузки основной HTTPS-страницы: домен, время, код ответа или тип сетевой ошибки. URL-пути, query string, cookies и тела запросов не передаются. Перезагрузка страниц и повторение POST не выполняются. После успешного переподбора повторите открытие страницы самостоятельно.

Расширение не меняет настройки прокси. Управление остаётся в консоли. API браузера использован по [документации Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest).

## Диагностика и данные

- `routes.sqlite3`: локальные домены, результаты выбора и последние 2000 событий. Данные остаются после перезапуска.
- `config.json`: способы и явно заданные группы доменов.
- `token.txt`: локальный API-ключ; не добавляйте его в GitHub и не отправляйте вместе с логами.
- `backend.log`: ошибки фонового процесса; файл не включается автоматически в архив.
- ZIP из пункта `6`: версия, ОС, способы и события. Имена доменов заменяются метками `service-N`, сетевой отпечаток исключается. Архив не отправляется автоматически. Пути URL и токен не включаются.

API и CONNECT-прокси слушают только `127.0.0.1`. Изменение состояния через API требует ключа; дополнительно проверяются Host и Origin. Публичный локальный `/proxy.pac` содержит только правила маршрутизации. Loopback не является изоляцией от другого процесса того же пользователя.

## Разработка и проверки

Для разработки достаточно Python 3.10+:

```bash
python -m pathfinder ui
python -m pathfinder serve --data-dir ./scratch-data
python -m unittest discover -s tests -v
node --test tests/test_pac.cjs
```

Сетевые тесты используют только loopback. TLS-тест создаёт временный сертификат через `openssl`, проверяет настоящий TLS-сеанс через CONNECT с дроблением ClientHello и отдельно отказ от недоверенного сертификата. Если `openssl` недоступен, этот тест пропускается. Проверка на Linux не равнозначна проверке PowerShell, реестра Windows, расширения в браузере или обхода ТСПУ.

Для приватного форка сохранена опция `-PrivateRepository`: установите GitHub CLI, выполните `gh auth login`, скачайте установщик с авторизацией и передайте эту опцию вместе с `-Repository owner/repo`.
