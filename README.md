# Pathfinder

Локальный инструмент для Windows 10/11: настраивает обход DPI, проверяет доступные способы и сохраняет найденные маршруты отдельно для каждой сети. Установка и управление — в терминале. Отдельно запускать zapret или ByeDPI не требуется.

**Версия 0.3.0.** По умолчанию все поддерживаемые публичные HTTPS/WSS-домены обрабатываются через встроенный обход; `.ru` открывается напрямую. Старые стандартные исключения для VK, `.su`, `.рф` и CDN удаляются при обновлении. Локальные адреса и неподдерживаемые протоколы сохраняют прямой доступ.

## Установка и обновление

Закройте прежнее меню через **0**, остановите zapret и полностью закройте браузер. В обычном PowerShell:

```powershell
irm https://raw.githubusercontent.com/de1evly/ggbb/main/install.ps1 | iex
```

При запуске автоматически включаются пользовательские настройки прокси Windows и начинается автонастройка. Она показывает прогресс, сохраняет прошедшие проверки маршруты и перечисляет нерешённые проблемы. Установка использует публичный GitHub и python.org; для скачивания нужен доступ к этим ресурсам.

Системный Python, Git и вход в GitHub не нужны. Используется переносимый Python 3.14.10 и официальный ByeDPI 0.17.3. Установщик проверяет Git blob SHA исходников и закреплённые SHA-256 архивов Python/ByeDPI и исполняемого файла ByeDPI. На ARM64 используется x86-сборка ByeDPI через эмуляцию Windows; этот вариант отдельно не проверен.

Исходники: `%LOCALAPPDATA%\PathfinderApp`. Данные и сохранённые решения: `%LOCALAPPDATA%\Pathfinder`.

Последующий запуск:

```powershell
& "$env:LOCALAPPDATA\PathfinderApp\Pathfinder.cmd"
```

Меню без включения системного прокси:

```powershell
& "$env:LOCALAPPDATA\PathfinderApp\Pathfinder.cmd" -NoProxy
```

Выход через **0** или Ctrl+C восстанавливает прежние пользовательские настройки прокси. После аварийного закрытия:

```powershell
& "$env:LOCALAPPDATA\PathfinderApp\Pathfinder.cmd" -RestoreProxy
```

## Автоматическое сканирование

Автопроверка запускается при первом открытии меню с включением прокси после запуска фонового процесса. Повторный запуск — пункт **10**, Enter для всех сервисов или название/домен для одного. Проверяются YouTube, Discord, ChatGPT, Telegram Web и до 12 недавно наблюдавшихся доменов. Для произвольного домена выполняется ограниченный GET главной страницы.

Проверяются все включённые способы, до трёх проб одновременно. Программа сравнивает результаты и сохраняет самый быстрый способ, прошедший все проверки соответствующего адреса или явно настроенной группы. Разные адреса сервиса могут использовать разные способы; постоянный единый внешний IP для учётной записи не гарантируется.

| Сервис | Базовые проверки |
| --- | --- |
| Discord | JSON публичного API Gateway, страница `/app`, настоящий WebSocket Upgrade с проверкой `Sec-WebSocket-Accept` |
| YouTube | JSON метаданных известного публичного видео и его миниатюра |
| ChatGPT | GET страницы с ожидаемым маркером; большая страница проверяется по ограниченному префиксу |
| Telegram Web | GET страницы приложения с ожидаемым маркером, при необходимости по префиксу |

Это отдельные запросы без cookies, паролей и входа в учётную запись. Ответы ограничены 64 КиБ, проверяется TLS-сертификат. JSON и маркеры проверяются в теле ответа; для WebSocket требуется корректный ответ 101 и подтверждение случайного ключа. HTTP 403/451 и неподходящий ответ не сохраняются как успешный результат автонастройки. Редиректы автоматически не проходятся.

Проверенный префикс страницы сохраняется с отдельной пометкой `content_prefix_ok`. Он подтверждает только полученный фрагмент, а не полную загрузку страницы. Обычный GET 200 без специального маркера также не доказывает работу всего сервиса. Даже маркер в HTML может присутствовать на странице защиты сайта.

В SQLite сохраняются маршрут и набор проверок, которыми он подтверждён. Восстановление после сбоев и фоновая проверка продолжают использовать эти проверки. Смена сети или конфигурации во время сканирования отменяет применение устаревшего результата. Если способов нет или они не прошли проверки, прежние настройки сохраняются и проблема остаётся в отчёте.

Сканирование не обходит все существующие сайты интернета. Неизвестные домены обрабатываются при обращении; расширенная проверка использует перечисленные профили и недавно наблюдавшиеся адреса.

## Windows и приложения

Для глобального режима одновременно задаются PAC и обычный HTTPS-прокси с исключением `.ru`. Это поддерживает приложения, которые читают ручной прокси, но не используют PAC. Изменяются только пользовательские `AutoConfigURL`, `ProxyEnable`, `ProxyServer`, `ProxyOverride`; исходные значения сохраняются и восстанавливаются. Изменения другого инструмента при выходе не перезаписываются.

Если базовые проверки Discord прошли, автонастройка пытается запустить установленный Discord с явным параметром локального прокси. Поддерживаются обычная установка, PTB и Canary в LOCALAPPDATA. Уже работающий Discord принудительно не закрывается: программа сообщает, что его нужно полностью завершить через трей и запустить через пункт **11**.

**Discord, запущенный с явным прокси, зависит от работающего Pathfinder. После выхода из Pathfinder полностью закройте такой Discord и запустите обычным ярлыком.** Восстановление настроек Windows не удаляет параметры уже работающего процесса.

Пункт **12** проверяет состояние Discord/ChatGPT и наличие установленного TCP-соединения соответствующего процесса с нашим локальным прокси. Отсутствие соединения в момент проверки не доказывает, что приложение игнорирует прокси. Наличие соединения не подтверждает авторизацию или остальные функции. У ChatGPT нет отдельного проверенного способа запуска с параметром прокси в этой версии.

| Пункт | Действие |
| --- | --- |
| 1 | Сохранённые решения и состояние встроенного компонента |
| 2 | Матрица отдельных способов для домена, без применения |
| 3 | Сбросить сохранённый выбор и подобрать маршрут заново |
| 4 / 5 | Включить / восстановить настройки прокси Windows |
| 6 | Сохранить обезличенный ZIP диагностики |

| 9 | Подключить существующий локальный SOCKS, 0 — отключить его |

В пунктах 2/3/10 можно указать `домен:порт`. Поддерживаются TLS-порты 443, 8443, 8080. Пустой ввод в пункте 10 проверяет все встроенные профили.

## Способы обхода

Встроенный [ByeDPI 0.17.3](https://github.com/hufrea/byedpi/tree/v0.17.3) запускается тремя процессами на `127.0.0.1`: `dpi-disorder`, `dpi-oob`, `dpi-tlsrec`. Процессы принадлежат Windows Job Object и завершаются при остановке фонового процесса Pathfinder. Служба и драйвер перехвата пакетов не устанавливаются, upstream bat-скрипты не исполняются. SOCKS UDP выключен.

По умолчанию `bypass_only: true`: обычные прямые IPv4/IPv6-маршруты не участвуют в выборе для управляемых доменов. При отказе всех способов программа не переключает эти домены напрямую. Прямой доступ применяется к `.ru` и техническим исключениям PAC. Если клиент игнорирует прокси или не смог получить PAC, его поведение контролирует сам клиент — это не kill switch.

HTTPS не расшифровывается, сертификаты не подменяются. Прямые и встроенные локальные способы используют системный DNS; DoH/DoT не включается. IP провайдера сохраняется. Ограничение сайта по стране, полный запрет IP или блокировка DNS могут требовать других способов или внешнего выхода. Один код 403 не определяет причину отказа.

Внешний выход подключается через уже работающий доверенный SOCKS на loopback, пункт 9. Pathfinder не устанавливает такой клиент автоматически и не использует случайные публичные прокси.

## Границы поддержки

Поддерживаются HTTPS и WSS поверх TCP у клиентов, использующих системный HTTP-прокси или явно настроенный CONNECT-прокси. HTTP без TLS, UDP, QUIC, Discord voice, WebRTC, произвольные TCP-приложения и клиенты, игнорирующие прокси, не покрываются. Это не системный TUN/VPN. Успех публичного API/WebSocket не доказывает работу авторизации, всех CDN, голосовых звонков или всех функций приложения.

Автонастройка выбирает из реализованных способов. Она не гарантирует доступ ко всем ресурсам и не создаёт иностранный IP. Нормальная скорость прямого подключения не гарантируется: пересылка, проверки и особенности выбранного способа добавляют расходы. Для сравнения скорости выключите прокси пунктом 5 и полностью перезапустите браузер; используйте один и тот же сервер измерения.

## Настройки и данные

Конфигурация: `%LOCALAPPDATA%\Pathfinder\config.json`. После ручного изменения перезапустите Pathfinder. Основные поля:

- `auto_manage: true`: охват всех поддерживаемых публичных HTTPS-доменов;
- `bypass_only: true`: выбор только встроенного обхода и подключённого SOCKS;
- `direct_domains: ["*.ru"]`: прямые исключения;
- `dpi_engine_enabled: true`: запуск встроенного компонента;
- `services`: явно заданные группы доменов, при необходимости общего маршрута.

Старый стандартный список прямых исключений мигрирует в `["*.ru"]`. Явно изменённые пользователем списки сохраняются. Чтобы строго применить только `.ru` после прежней ручной настройки, задайте указанное значение `direct_domains`.

Локально сохраняются `routes.sqlite3`, `config.json`, `token.txt`, `backend.log`, `proxy-backup.json`. API-ключ не публикуется. ZIP из пункта 6 содержит обезличенные домены `service-N`, результаты проб и ограниченный журнал подключений, без токена, URL-путей, содержимого страниц и командных строк приложений. Автоматической отправки нет. API и прокси слушают только loopback; API требует ключ и проверяет Host/Origin.

## Разработка

Python 3.10+, стандартная библиотека. На Linux можно проверять Python-движок и локальные TLS-пробы; встроенный Windows-компонент и реестр там не применяются.

```bash
python -m unittest discover -s tests -v
node --test tests/test_pac.cjs
python -m pathfinder serve --data-dir ./scratch-data
```

Тесты используют временные данные и loopback; TLS-сертификат создаётся через openssl. Linux-тесты не подтверждают запуск на Windows и обход ограничений конкретного провайдера. GitHub Actions workflow запускается вручную.

Для запуска из распакованной копии: `powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -LocalSource .`. Для приватного форка сохранена опция `-PrivateRepository` с авторизацией через GitHub CLI.
